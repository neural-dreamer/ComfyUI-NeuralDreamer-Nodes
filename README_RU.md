## Установка

Склонируйте репозиторий в `ComfyUI/custom_nodes` и перезапустите ComfyUI:

```bash
cd ComfyUI/custom_nodes
git clone https://github.com/neural-dreamer/ComfyUI-NeuralDreamer-Nodes.git
```

Дополнительные Python-зависимости не нужны.

## Подключение нод

У нод, которые принимают или отдают несколько значений, не больше одного входа и одного выхода, оба типа `ND_PARAMS` (провод параметров) и без подписи. Значения подаются и снимаются через **ND Pack Parameters** и **ND Unpack Parameters**. ND Show Any As Text и ND Slider работают с одним обычным значением и подключаются напрямую.

- Подключите Pack ко входу ноды, и на Pack появятся ровно те входы, которые эта нода ждёт (например, `images` и `image` у Variant Preview Selector).
- Подключите Unpack к выходу ноды, и на Unpack появятся её выходы, с именами и типами.
- Если вытянуть провод параметров в пустое место, первым в поиске нод будет Pack (если тянуть от входа) или Unpack (если от выхода).
- Поле само может быть проводом параметров; оно открывается ещё одним Unpack.

## ND Variant Preview Selector

<img src="docs/images/variant-preview-selector.png" alt="ND Variant Preview Selector" width="640">

Показывает батч изображений миниатюрами и главным превью. Вариант выбирается кликом или стрелками на клавиатуре.

**Эта нода не является апскейлером** и сама ничего не увеличивает. Кнопка **Upscale** необязательная (её можно отключить в настройках) и служит другой цели: она отправляет выбранный вариант в апскейлер, который вы собираете в воркфлоу после селектора, на любых нодах апскейла, в том числе сторонних. Генерация при этом берётся из кэша, а результат апскейла можно показать обратно в ноде.

**Поля входа** (через Pack Parameters)

| Поле | Тип | Описание |
|---|---|---|
| `images` | IMAGE | Батч вариантов |
| `image` | IMAGE, опционально | Результат апскейла, показывается в ноде. При обычном Run не вычисляется |

**Поля выхода** (через Unpack Parameters)

| Поле | Тип | Описание |
|---|---|---|
| `multi_variant` | BOOLEAN | Состояние тумблера Multi-Variant |
| `selected_index` | INT | Номер выбранного изображения, с 0 |
| `upscale` | BOOLEAN | `true` только при запуске кнопкой Upscale |

**Интерфейс**

- Лента миниатюр и главное превью с бейджем позиции (`2/4`). В интерфейсе варианты нумеруются с 1; `selected_index` — индекс с 0, поэтому вариант 1 выдаёт `0`.
- Сверху главное превью, под ним размер показанного изображения (`1024 × 1536 px`; в режиме сравнения оба размера), ниже миниатюры и кнопка **Upscale**. Кнопка доступна, когда на превью вариант из батча.
- Тумблер **Multi-Variant** внизу слева. Его подпись можно переименовать в настройках (*Toggle label*); меняется только текст в ноде, выход по-прежнему `multi_variant`.
- Кнопка **Compare** появляется на результате апскейла и включает ползунок «до/после» между изображением, отправленным на апскейл, и результатом.
- Кнопка с шестерёнкой открывает настройки: имена файлов, сохранение, кнопку Upscale и лайв-превью.
- **Live preview** (по умолчанию выключено, в настройках): пока генерируются варианты или проход апскейла, главное превью показывает кадры сэмплера с бейджем `LIVE 12/30` (шаги сэмплера). Кнопка с глазом внизу слева на превью скрывает или показывает их в этой ноде. Показывается всегда то, что генерируется прямо сейчас (при нескольких сэмплерах — работающий, при батче — его первое изображение); миниатюры хранят прошлые результаты, пока не придут новые. С [ND Live Preview Bridge](#nd-live-preview-bridge) перед сэмплерами кадры идут от бриджа, а стандартное превью сэмплера ComfyUI на этот запуск отключается, в том числе когда живое превью скрыто глазиком. Без бриджа нода показывает превью самого ComfyUI: они должны быть включены (Settings → Comfy → Execution → Live preview method).
- Колесо мыши над нодой масштабирует canvas, а перетаскивание средней кнопкой перемещает его. Если миниатюры не помещаются, ленту можно прокрутить колесом с Shift или горизонтальным свайпом тачпада.
- **Preview with Metadata** (настройки, по умолчанию выключено): записывает промпт и workflow в превью, как в сохранённые файлы. Тогда превью, вытащенное из ноды или открытое в новой вкладке, содержит их. Изображения можно перетаскивать из ноды, например в блок ND Load Images.

**Сохранение**

| Настройка | Описание |
|---|---|
| Toggle label | Подпись тумблера, по умолчанию `Multi-Variant`. Только для интерфейса ноды |
| File name | Общее начало имени файлов, по умолчанию `ND_Image`. Поддерживаются подпапки, например `shots/hero` |
| Variant name | Добавляется после имени файла для вариантов: `ND_Image_variant`. Если поле пустое, варианты сохраняются под одним именем файла |
| Upscaled name | Добавляется после имени файла для результата апскейла: `ND_Image_upscaled` |
| Upscale button | Показывает кнопку Upscale (включено по умолчанию). Когда выключено, каждый входящий батч сохраняется |
| Save variants | Сохраняет входящий батч в папку `output` при каждом обычном Run. Пока кнопка Upscale выключена, всегда включено |
| Live preview | Показывает кадры сэмплера в ноде во время генерации (по умолчанию выключено). Только для интерфейса ноды |

Файлы нумеруются так же, как в стандартной ноде Save Image: `ND_Image_variant_00001_.png`. Результат апскейла сохраняется всегда. В workflow, сохранённых со старым именем по умолчанию `ND_variant`, при загрузке оно меняется на `ND_Image`. Метаданные workflow встраиваются так же, как в стандартной ноде Save Image. Пока вкладка браузера открыта, нода сохраняет изображения при переключении на другой workflow и обратно, вместе с выбранным вариантом и результатом апскейла; запуск, завершившийся за это время, тоже подхватывается. После обновления страницы или перезапуска ComfyUI нода пустая до следующего Run, а заново загруженный workflow начинается с варианта 1.

## ND Live Preview Bridge

<img src="docs/images/live-preview-bridge.png" alt="ND Live Preview Bridge" width="760">

Ставится на провод `MODEL` перед сэмплерами (после загрузчика модели и её патчей, например LoRA или ModelSampling). Пока сэмплеры работают, бридж отправляет маленькое превью генерируемого изображения (при батче — первого) в [ND Variant Preview Selector](#nd-variant-preview-selector) с включённым *Live preview*. Модель проходит без изменений.

| Вход / выход | Описание |
|---|---|
| `model` → `model` | Модель с хуком, который читает каждый шаг сэмплера |
| `preview_data` | Привязка к конкретному селектору: подключите к Pack, который питает селектор (у Pack для этого появляется пин `preview_data`). Селектор, получающий изображения, сделанные через бридж, получает кадры и без неё |
| method | `latent2rgb` (быстро, примерные цвета) или `taesd` (чётче; нужен декодер TAESD в `models/vae_approx` и немного времени GPU) |
| size | Длинная сторона кадров, по умолчанию 384 px |

- Кадры отправляются, только пока у селектора, который питает бридж, включено и показано *Live preview*; включение и выключение никогда не перезапускает сэмплинг.
- Работает при любом Live preview method в ComfyUI и через сабграфы.

## ND Variant Slider Selector

<img src="docs/images/variant-slider-selector.png" alt="ND Variant Slider Selector" width="560">

Целочисленный слайдер с тумблером Multi-Variant и кнопкой Upscale. Как и Preview Selector, сама ничего не увеличивает: кнопка только запускает ветку апскейла, которую вы собираете в воркфлоу. Входа у ноды нет. Диапазон слайдера (min, max, step) задаётся кнопкой с шестерёнкой или в свойствах ноды.

| Поле выхода | Тип | Описание |
|---|---|---|
| `multi_variant` | BOOLEAN | Состояние тумблера Multi-Variant |
| `value` | INT | Значение слайдера |
| `upscale` | BOOLEAN | `true` только при запуске кнопкой Upscale |

## ND Show Any As Text

<img src="docs/images/show-any-as-text.png" alt="ND Show Any As Text" width="480">

Принимает на вход `value` любой тип и показывает его как текст.

| Значение | Как показывается |
|---|---|
| Строка | Как есть |
| Число, boolean | Само значение |
| Список, словарь (latent, conditioning, ...) | Отформатированный JSON |
| Тензор, массив (image, mask, ...) | Форма, тип данных и min/max/mean; сами значения — только для очень маленьких тензоров |

Список на входе (несколько элементов) выводится поэлементно. Вывод ограничен 100 000 символов.

**Вкладки**

- **Preview** — первая вкладка, открыта по умолчанию. У неё более светлый фон и приглушённый текст (у вкладок заметок фон темнее, а текст ярче), она только для чтения; текст можно выделить и скопировать.
- **+** добавляет вкладку-заметку (`Note 1`, `Note 2`, ...). Двойной клик по названию переименовывает вкладку.
- Кнопка × удаляет вкладку-заметку. Если в ней есть текст, нужен второй клик.
- Заметки и последний текст превью сохраняются в workflow и не пропадают после перезагрузки workflow или ComfyUI. Превью меняется только при поступлении новых входных данных.
- Навигация по canvas над нодой работает так же, как у Variant Selector. Колесо прокручивает текстовое поле, только если текст в нём не помещается; иначе, а также с Ctrl, оно масштабирует canvas.
- Если вкладок много, полоса прокручивается: кнопки со стрелками (удерживайте для непрерывной прокрутки), колесо или Shift+колесо. Кнопка **Copy** над текстом Preview копирует его.

## ND Slider

<img src="docs/images/slider.png" alt="ND Slider" width="560">

Слайдер в одну строку на всю ширину ноды, всегда по центру по высоте. Шестерёнка слева открывает настройки, выходной пин справа, на одном уровне со слайдером. Входов нет.

| Настройка | Описание |
|---|---|
| Type | `Integer` или `Float`. Задаёт тип выхода: INT или FLOAT |
| Min, Max | Диапазон слайдера |
| Step | Шаг слайдера. Для целых округляется и не меньше 1 |

- Текущее значение показано справа от слайдера; по клику его можно ввести с клавиатуры. Нода высотой в одну строку, как стандартные виджеты.
- При смене типа провода ко входам, которые не принимают новый тип, удаляются.
- Значение и настройки сохраняются в воркфлоу.

## ND Character Builder

<img src="docs/images/character-builder.png" alt="ND Character Builder" width="480">

Character Prompt Builder. Слева колонка кнопок разделов с иконками, нарисованными по референсным фигурам: General (женщина и мужчина), Whole body, Hair, Face, Neck, Shoulders & Back, Chest, Arms, Hands & Nails, Waist, Hips & Butt, Legs, Feet, Genitals. Кнопка открывает параметры раздела справа; при наведении видно, что в нём задано. Причёски, чёлки и форма ногтей выбираются по картинкам. Вход: необязательный провод `ND_PARAMS` с полем `seed`; подключите Pack Parameters и подайте в него seed (например, от ноды seed). Своего виджета seed у ноды нет; без провода seed равен 0, и случайные значения от запуска к запуску не меняются.

| Часть | Параметры |
|---|---|
| General | Пол, возраст (18–90), раса (человек или фэнтези: эльф, тёмный эльф, полуэльф, дварф, гном, полурослик, гоблин, орк, полуорк, тифлинг, демон, суккуб, инкуб, ангел, вампир, они, фея, кошачий, лисий, волчий и кроличий народ, драконорождённый), внешность, тон кожи (в том числе зелёный, серый, синий, красный и фиолетовый, каждый в обычном и тёмном оттенке, для фэнтезийных рас), текстура кожи |
| Face | Форма лица, размер, форма и цвет глаз, брови, нос, губы, рот, челюсть, подбородок, скулы |
| Hair | Цвет, длина, структура, причёска, чёлка |
| Body | Рост, тип фигуры, количество жира, шея, ширина плеч, длина рук и ног |
| Muscle | Общая мускулатура и отдельные значения для рук, спины и плеч, пресса, ягодиц и ног |
| Waist & Hips | Талия, живот, ширина бёдер |
| Chest | Грудная клетка; для женщин размер, форма и упругость груди; для мужчин грудные мышцы и волосы на груди; размер и цвет ареол, размер и форма сосков |
| Butt & Legs | Размер, форма и упругость ягодиц, размер и форма ляжек, промежуток между бёдрами, икры |
| Hands & Nails | Размер кистей, длина и толщина пальцев, тип, длина, форма, цвет и покрытие ногтей |
| Feet | Размер и ширина стопы, подъём, длина пальцев, цвет и покрытие педикюра |
| Genitals | Настройка анатомических элементов (только для взрослых персонажей, по умолчанию скрыт) |

- Раздел Genitals по умолчанию скрыт. Отметьте *Genitals* на панели сверху, чтобы показать его; пока галочка снята, его значения не используются (воркфлоу, где в нём уже есть значения, открываются с включённым разделом). Раздел предназначен только для вымышленных взрослых персонажей (18+) и не должен использоваться для изображения реальных людей; при включении об этом напоминает короткое сообщение.
- Точка на кнопке раздела показывает, что в нём есть значения: золотая — заданные, фиолетовая — случайные.
- При наведении на значение или на подчёркнутое название параметра появляется подсказка с описанием.
- Параметры одного пола (грудь у женщин, грудные мышцы и волосы на груди у мужчин) скрываются, пока выбран другой пол, и не попадают в текст; их значения сохраняются на случай, если пол сменят обратно.
- Некоторые варианты отключают другие параметры: плоская грудь убирает форму и упругость груди, French, Bare или Clear coat убирают цвет лака. Такие параметры панель показывает как неиспользуемые.
- *Same as hands* (в зоне Feet) копирует цвет и покрытие лака на педикюр.
- Каждый параметр либо *не задан* (не попадает в текст), либо задан значением, либо случайный. Повторный клик по выбранному значению сбрасывает его; × тоже сбрасывает.
- **Random** (кнопка с кубиком): значение выбирается по `seed` с входного провода при каждом запуске. У каждого параметра свой бросок, поэтому если зафиксировать один параметр, остальные не меняются. Пока random включён, клик по значениям задаёт, из каких выбирать; для возраста задаётся диапазон. *All random* делает случайной всю зону.
- **All random** (на панели сверху): все параметры во всех разделах сразу становятся случайными. Клик по значениям по-прежнему сужает, из чего выбирать. Значения, заданные вручную, сохраняются и возвращаются, когда режим выключен; *Fix random* превращает последнего выпавшего персонажа в фиксированные значения и выключает режим.
- **Race** принимает до трёх значений сразу, чтобы смешивать расы: отметьте Elf и Fox-folk, и персонаж описывается как «of mixed elf and fox-folk blood», с чертами обеих рас (заострённые уши, лисьи уши, хвост) и тегами обеих. Четвёртый клик не принимается (строка вздрагивает); повторный клик по отмеченной расе убирает её. Случайный выбор берёт одну расу.
- Случайный выбор берёт человека примерно так же часто, как все фэнтезийные расы вместе, а фэнтезийные цвета кожи — только для подходящих рас (зелёная кожа для орков и гоблинов, красная для тифлингов и демонов и так далее).
- **Avoid conflicts**: случайный выбор пропускает значения, несовместимые с остальными, например пикси при волосах до талии, морщины в 25 лет или полноту с кубиками пресса. Значения, заданные вручную, не меняются.
- **Fix random** превращает последние выпавшие значения в фиксированные, чтобы понравившегося персонажа можно было дорабатывать вручную.
- **Presets**: введите имя и нажмите *Save*, чтобы сохранить все настройки ноды (все параметры, случайные значения и их наборы, форматы и Avoid conflicts). Клик по пресету загружает его и заменяет текущие настройки. × удаляет пресет (повторный клик подтверждает). Сохранение под уже существующим именем перезаписывает пресет. Пресеты хранятся в папке пользователя ComfyUI (`user/<user>/neural_dreamer/character_presets.json`), поэтому доступны в любом workflow.
- **Format**: *Natural* (предложения, для Flux 2 и Krea 2) и *Tags* (теги через запятую: теги Danbooru, например `1girl`, `long hair`, `wide hips`, там, где на Danbooru есть тег, и простые теги, например `heart-shaped face`, `slavic appearance`, `27 years old`, для остального). Можно включить оба; хотя бы один включён всегда.
- Возраст ограничен 18–90 и в браузере, и повторно на сервере.
- Выход: один провод `ND_PARAMS`. Unpack Parameters раскрывает его в `Full Description` (весь персонаж) и по тексту на каждую часть: `General`, `Face`, `Hair`, `Body`, `Muscle`, `Waist & Hips`, `Chest`, `Butt & Legs`, `Hands & Nails`, `Feet`, `Genitals` и `Negative` (теги анатомических элементов, которых у персонажа нет; пусто, пока раздел Genitals не задан). Если в части ничего не задано, её выход — пустая строка.
- **Create / Edit**: переключатель вверху задаёт, чем будет текст. *Create* описывает персонажа для модели text-to-image. *Edit* пишет инструкции для модели редактирования изображений: каждый заданный параметр становится одним предложением (*Add*, *Replace* или *Remove* для каждой части), в конце идёт фраза «остальное не менять», которую можно отключить в настройках. *All random* в Edit не используется.
- **Вход Outfit**: подключите ND Outfit Builder через Pack Parameters (поле `outfit`). Его текст добавляется к описанию, а части тела, закрытые одеждой, не попадают в текст (например, татуировка под брюками).
- **Extra prompt** (внизу) добавляет произвольный текст новым абзацем. Признаки расы (например, рога) можно отключать по одному.
- **Язык**: см. [Общие возможности билдеров](#общие-возможности-билдеров).
- Кроме текстов, на выходе есть `Character Builder Out` — собранный персонаж, который читает ND Pose Builder.
- Формулировки лежат в `js/character_builder.json`, их можно править; сервер перечитывает файл при изменении (для обновления панели перезагрузите страницу).
- Всё сохраняется в воркфлоу, включая открытый раздел и последние выпавшие значения, которые показывает панель.

## ND Outfit Builder

Описание наряда. Слева колонка слотов: Style, Head, Top, Outerwear, One-piece, Bottom, Underwear, Legwear, Footwear, Gloves, Accessories. У каждого слота свои параметры (тип, цвет, узор, материал, посадка, длина, состояние). Вход: необязательный провод `ND_PARAMS` с полем `seed`.

- **Style**: до трёх стилей одновременно (casual, business, cyberpunk, steampunk, medieval, fantasy и другие). Стили сужают выбор *random* и попадают в текст («a cyberpunk and steampunk outfit: ...»). Wearer (женский, мужской, нейтральный) фильтрует вещи и задаёт местоимения. Необязательная палитра ограничивает цвета, которые может выбрать random.
- Цельная одежда (one-piece) отключает Top и Bottom. У каждого типа вещи можно ввести своё значение (*Custom*).
- **State** (мокрая, расстёгнутая, распахнутая, порванная, спущенная с плеча и другие) меняет текст и то, какие части тела закрыты одеждой.
- **Explicit** (настройки, по умолчанию выключено): показывает вещи и состояния для взрослых. Нода предназначена только для вымышленных взрослых (18+) персонажей.
- Каждый параметр: *не задан*, задан или случайный; random, пресеты, *Fix random* и *Avoid conflicts* работают как в Character Builder. Пресеты хранятся в `user/<user>/neural_dreamer/outfit_presets.json`.
- Create и Edit работают как в Character Builder; в Edit у каждого слота есть *Add*, *Replace* и *Remove*. Текст Edit может быть полными инструкциями или одним простым предложением (настройки).
- Выход (через Unpack Parameters): `Outfit` (текст) и `outfit` — бандл для Character Builder. Подключите его через Pack Parameters (`outfit`) к Character Builder.

## ND Pose Builder

Описание позы для одного персонажа. Вход: необязательный провод `ND_PARAMS` с полями `seed` и `character` (`Character Builder Out` ноды ND Character Builder; без него у ноды есть свой параметр *Subject*).

- **Simple** (по умолчанию): слева категории (Photoshoot, Natural, Sitting, Lying, Heroic & Action, Dance & Fitness, Sensual и категории для взрослых), для каждой — сетка готовых поз, а под ней несколько быстрых настроек (взгляд, выражение, ноги и т. д.). Выбор позы задаёт параметры, которые за ней стоят; если изменить один из них, поза помечается как *modified*.
- **Advanced**: каждая часть тела отдельно (поза тела, торс, голова и лицо, руки и кисти, ноги) и дополнительные разделы для предметов и деталей (разделы для взрослых — за Explicit). Руки описываются как «one hand ... the other hand».
- Позы и варианты, которым нужна анатомия, которой нет у подключённого персонажа, скрыты (Simple) или приглушены (Advanced), и random их не выбирает.
- **Explicit** (настройки, по умолчанию выключено) показывает категории и разделы для взрослых. Только для вымышленных взрослых (18+) персонажей.
- Random, пресеты (`pose_presets.json`), *Fix random*, Create / Edit и формат промпта работают как в остальных билдерах.
- Выход (через Unpack Parameters): `Pose Description`, `Full Description` (персонаж, наряд и поза одним текстом) и `Pose Builder Out`, который читает ND Composition Settings. Камера не входит в позу: для неё используйте ND Composition Settings после Pose Builder.

## ND Composition Settings

Камера кадра в одном из двух режимов.

- **Single shot** (один кадр): высота камеры, вид вокруг объекта (спереди, три четверти, сбоку, сзади), наклон, дистанция, кадрирование и акцент, особые точки зрения (от первого лица, селфи, зеркало и другие), объектив (фокусное расстояние, глубина резкости, фокус, тип камеры, эффекты, экспозиция) и положение объекта в кадре (позиция, размер, правило композиции). Работают и Create, и Edit.
- **Collage** (коллаж): до 8 панелей на одном холсте, для character sheet или коллажа. У каждой панели своя камера, кадрирование, объектив и размещение, а также своё место и размер на холсте: панели перетаскиваются и растягиваются по сетке. Шаблоны раскладки (ряд из трёх видов, turnaround, 2×2 и другие) создают панели сами. В тексте описаны лист, каждая панель и её положение словами.
- Вид вокруг объекта следует за позой: если Pose Builder сообщает, что персонаж стоит спиной к камере, остаются только виды сзади.
- **Камера из позы**: у готовых поз Pose Builder есть рекомендуемые кадрирование и ракурс; незаданные параметры камеры берутся оттуда, а всё, что вы задали вручную, главнее.
- **Входы** (через Pack Parameters): `seed`, `pose` (`Pose Builder Out` ноды Pose Builder) и `resolution`. Можно подключить несколько Pose Builder (`pose_2` ... `pose_8`); новый пустой пин появляется, как только использован последний, а каждая панель выбирает, какую позу показывать.
- **Update resolution** берёт ширину и высоту из подключённой ND Resolution (или из ноды с виджетами `width` и `height`); иначе размер задаётся в самой ноде.
- Выход (через Unpack Parameters): `Camera Description`, `Full Description` (персонаж, наряд, поза и камера) и `Composition Settings Out` (прямоугольники панелей и разрешение, для дальнейшего использования).
- Модели по-разному надёжно понимают «лево/право», наклон и положения панелей; в подсказках об этом сказано.

## Общие возможности билдеров

Эти возможности общие для четырёх билдеров промптов (Character, Outfit, Pose, Composition Settings).

- **Язык**: интерфейс на английском, русском или китайском (шестерёнка, *Language*). *All nodes* задаёт язык для всех билдеров, *This node* переопределяет его для одной ноды. По умолчанию язык берётся из ComfyUI. Всплывающие подсказки тоже переведены и сохраняют строку `EN:` с английским названием. Текст самого промпта всегда английский.
- **Темы, масштаб интерфейса и пресеты** общие; пресеты каждой ноды лежат в отдельных файлах в пользовательской папке ComfyUI.
- Ноды предназначены только для вымышленных взрослых (18+) персонажей.

## ND Load Images

<img src="docs/images/load-images.png" alt="ND Load Images" width="760">

Модульный загрузчик изображений. Количество блоков (1–20) задаётся в настройках ноды (шестерёнка справа вверху); кнопок добавления и удаления на самой ноде нет. Блоки раскладываются сеткой, которая подстраивается под размер ноды.

**Блок**

- **Upload Image** открывает окно выбора файла; изображение можно и перетащить на блок. Новый блок начинается с `example.png` из папки input.
- **Mask** открывает редактор масок ComfyUI для изображения блока. Без маски блок выдаёт пустую маску. Крестик на кнопке удаляет маску.
- **Keep Proportion**: `crop`, `pad white`, `pad black`, `pad edge` (повторяет пиксели края), `pad edge color` (заливает каждую сторону усреднённым цветом прилегающего края изображения), `stretch` (по умолчанию `crop`).
- **Edit** открывает редактор для кадрирования, поворота и отражения. Правки не разрушают исходник, их можно изменить позже.
- Кнопка с круглой стрелкой в правом верхнем углу изображения сбрасывает блок на `example.png` и убирает маску, поворот, отражение и кадрирование.
- **Слайдер**: название, минимум, максимум и шаг задаются в настройках блока (по умолчанию `Strength`, 0.0–1.0, шаг 0.1).
- Кружок слева вверху включает и выключает блок; выключенный блок становится бледным.
- Порядок блоков меняется перетаскиванием за ручку справа вверху. У блока с *Lock Order Position* вместо ручки замок, и он остаётся на своём месте.

**Настройки блока** (шестерёнка в заголовке блока): *Block name*, название блока (пусто означает `Image N`; это только подпись в интерфейсе, она хранится в workflow и остаётся за блоком при перестановке; соответствующий выход Unpack показывает её как `<название> Parameters`); показ кнопки Mask, селектора Keep Proportion и слайдера; меняет ли Keep Proportion изображение или только передаётся на выход; метод масштабирования для этого (`nearest-exact`, `bilinear`, `area`, `bicubic`, `lanczos`; по умолчанию `lanczos`); название, диапазон и шаг слайдера; *Lock Order Position*: блок нельзя перетащить, а при перестановке других блоков они обходят его. Выключенная опция убирается и из выходов блока (выход маски есть всегда).

**Настройки ноды**: количество блоков; *Hide block settings* скрывает шестерёнки блоков, чтобы готовую настройку не сбить случайно.

**Порядок обработки** в каждом блоке: маска (рисуется на исходном изображении) → поворот → отражение → кадрирование → Keep Proportion под целевой размер выбранным в блоке методом масштабирования, если блок его применяет. Целевой размер берётся из `width` и `height` на входе; без них это размер изображения первого включённого блока после его правок, и остальные блоки подгоняются под него. Если включённых блоков нет, ничего не масштабируется. В режимах pad маска дополняется нулями (в `pad edge` — повтором края).

| Сторона | Поля | Описание |
|---|---|---|
| Вход (опционально) | `width`, `height` (INT) | Целевой размер для всех блоков. Подключите Pack Parameters, он создаст оба входа. Без входа размер задаёт первое включённое изображение |
| Выход | `Image N Parameters` | По полю на блок. Поле блока распаковывается в `image`, `mask`, `keep_proportion`, значение слайдера и `enabled` |

Все настройки, файлы, маски и правки хранятся в workflow.

Значения кэшируются по каждому выходу: изменение ползунка или одного блока заново запускает только ноды, которые используют это значение, а не всё после ND Load Images. В каждом блоке кнопка-глаз показывает итоговое изображение так, как нода его выдаст (после правок и Keep Proportion к текущему целевому размеру). На блок можно перетащить изображение из ND Variant Preview Selector или по URL.

## ND Resolution

Задаёт размер изображения по соотношению сторон и одному числу. Соотношение — пресет (1:1, 4:3, 3:2, 16:9, 21:9 и вертикальные) или введённое вручную (например, `5:4`). Число — мегапиксели (1 = 1024 × 1024 пикселей), длинная сторона или короткая, в зависимости от метода, выбранного в настройках (шестерёнка). Там же задаётся кратность, до которой округляются обе стороны (8, 16, 32 или 64). Размер показывается в ноде по мере изменений.

Выход: один провод `ND_PARAMS`. Unpack Parameters открывает его в `width` и `height` (INT); подключите их к пустому латенту, ND Load Images или ND Composition Settings.

## ND Batch Images

Собирает изображения в один батч. Размер задаёт первое изображение; каждое следующее подгоняется под него теми же режимами, что Keep Proportion в ND Load Images (`crop`, `pad white`, `pad black`, `pad edge`, `pad edge color`, `stretch`). Сначала показано два входа, а новый пустой появляется, как только подключён последний (до 32). Вход может сам быть батчем: его изображения добавляются друг за другом в порядке пинов, пустые пины пропускаются. Выход: `images` (IMAGE).

## ND Multi Switch

Переключает сразу группы значений. Входы идут парами, `true N` и `false N`, на каждую пару один выход. Тумблер `condition` выбирает сторону, откуда берутся выходы: `out N` равен `true N` при включённом тумблере и `false N` при выключенном.

- Новая пара появляется, как только подключена последняя (до 32). Пары разделены тонкими линиями.
- У каждой пары свой тип данных. Его задаёт первый подключённый к ней провод с любой стороны: к входу `true` или `false` либо к выходу. Три пина пары получают этот тип и называются по пину на другом конце провода (`image (true)`, `image (false)`, `image (out)`). Когда у пары не остаётся проводов, она снова свободна (`true +`, `false +`, `out`). Пустая пара между занятыми остаётся, чтобы номера выходов не сдвигались. Имя, заданное через Rename Slot, сохраняется.
- Вычисляется только выбранная сторона: ноды, питающие другую сторону, ради переключателя не запускаются.
- Если на выбранной стороне пары ничего не подключено, а на другой подключено, этот выход блокирует ноды после себя: они пропускаются без ошибки.

## ND Any Switch

Пропускает один из своих входов. Целое число `index` выбирает какой (1 — первый пин); выбранный пин подсвечивается.

- Сначала два пина: первый и свободный с пометкой `+`. Новый `+` появляется, как только подключён последний (до 64). Каждый пин принимает любой тип независимо от остальных; подключённый пин называется `N: <имя источника>`.
- Единственный выход имеет свободный тип и подключается к любому пину.
- Вычисляется только выбранный вход, остальные игнорируются, как будто их провода никуда не ведут. Если подключено несколько загрузчиков моделей, работает только выбранный.
- Если выбранный пин пуст, выход тоже пуст, без ошибки.

## ND ON / OFF

Пропускает одно значение. При включённом тумблере `condition` (true) значение идёт на выход; при выключенном (false) ничего не выходит, как будто провода после ноды нет: необязательный вход, который она питала, считается неподключённым, а не отсутствующими данными. Пока тумблер выключен, вход не вычисляется.

- Один вход и один выход. Первый подключённый провод, к входу или к выходу, задаёт обоим пинам тип и имя.

**Как логические переключатели «опустошают» провод.** Если `index` или `condition` заданы в самой ноде (или приходят из ноды Primitive Int / Primitive Boolean), браузер убирает переключатель из отправляемого промпта: ноды после него соединяются прямо с выбранным источником либо теряют этот провод. Если значение приходит из другой вычисляемой ноды, переключатель остаётся в промпте и на «ничего» выдаёт `None`. Обязательный вход после пустого выхода ComfyUI сообщит как отсутствующий, как и у любого неподключённого провода. Export (API) отдаёт тот же обработанный промпт.

## ND Pack Parameters / ND Unpack Parameters

<img src="docs/images/pack-unpack.png" alt="Pack and Unpack Parameters" width="640">

Провод параметров (`ND_PARAMS`) несёт сразу несколько именованных значений, и такие провода можно вкладывать друг в друга.

- **ND Pack Parameters**: если его выход подключён к ноде этого пака, на нём появляются входы, которые эта нода ждёт, с нужными именами и типами. Иначе он принимает любые значения: новый вход появляется, когда занят последний, поле называется по подключённому выходу, а переименование входа переименовывает поле. Необязательные входы рисуются полыми кружками: все входы после первого, включая `+ value`, или поля, которые подключённая нода помечает как необязательные.
- **ND Unpack Parameters**: подключите провод параметров, и выходы создадутся сами, с именами и типами полей. Поле, которое само является проводом параметров (например, `Image 1 Parameters`), открывается ещё одним Unpack.
- Обе ноды прослеживают провода через reroute и границы сабграфов.

## Как работает Upscale

Селекторы не апскейлят. Кнопка Upscale только ставит запуск с `upscale = true`; что произойдёт с выбранным изображением, решает подключённая вами ветка апскейла (любые ноды апскейла, в том числе сторонние).

- **Run** ставит workflow в очередь с `upscale = false`. Провод в поле `image` у Pack селектора убирается из промпта, поэтому ветка апскейла не вычисляется.
- **Upscale** ставит workflow в очередь с `upscale = true` и индексом, выбранным в момент нажатия. Сиды в режиме randomize или increment у нод выше селектора сохраняют значения последнего Run, поэтому генерация берётся из кэша. Результат, подключённый к `image`, сохраняется и показывается в ноде.
- Выход селектора передаётся дальше через служебную ноду (ND Variant Values) со значениями, которые были в селекторе в момент запуска. От самого селектора ничего не зависит, поэтому его выход и вход можно вести через один сабграф или через Pack/Unpack по кругу без ошибки о циклическом соединении.
- Ветку апскейла нужно гейтить полем `upscale` (например, через switch-ноду).

## Добавление нод

Каждая нода — отдельный модуль в `nd_nodes/`. Новый модуль регистрируется добавлением его имени в `MODULES` в `nd_nodes/__init__.py`. Фронтенд-код кладётся в `js/`.

Новые ноды, которые передают несколько значений, следуют тому же правилу: один вход `ND_PARAMS` с именем `params` и один выход `ND_PARAMS` с именем `params`, оба без подписи. Чтобы Pack и Unpack строили пины для ноды, её поля регистрируются в браузере в общем реестре из `js/nd_common.js` (`ND_REG.consumers` для входа, `ND_REG.providers` для выхода). Имена классов делайте длиннее, чем `NDUnpack`: поиск нод сортирует ноды одного типа по самому короткому имени, и короткие ключи `NDPack` / `NDUnpack` держат Pack и Unpack наверху. Служебные ноды помечаются `DEV_ONLY = True`, чтобы не попадать в поиск.
